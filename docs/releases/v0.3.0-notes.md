# go-idempotency v0.3.0

**Release date:** 2026-09-05 · **Compare:** v0.2.0...v0.3.0

v0.3.0 completes the advertised integration layer: a stdlib-only `middleware`
package for at-most-once command dispatch (with a `net/http` `Idempotency-Key`
adapter), a contract suite that provably catches broken Stores, a runnable
end-to-end example, and the recipes and governance docs around them.

## Highlights

### Middleware: at-most-once dispatch, HTTP included

`middleware.NewCommand` wraps any command function so the side effect runs at
most once per key: the first call claims via `CheckAndRecord` and executes,
duplicates are rejected with `ErrDuplicate` without executing, and store
failures fail closed — the command does NOT run when the store's state is
unknown, because executing twice is the one unrecoverable outcome. The
`net/http` adapter maps the `Idempotency-Key` header to 400 (missing), 409
(duplicate), and 503 (store failure). Stdlib-only per
[ADR-002](../adr/002-middleware-module-boundary.md); proven by a
50-goroutine exactly-once test and fuzzed dispatch interleavings.

```go
place := middleware.NewCommand(store, time.Minute, func(ctx context.Context) error {
    return processPayment(ctx, orderID)
})
err := place(ctx, "order-42:place") // at most once per key within the TTL window
```

### The contract suite proves it can catch a broken Store

Every one of the 13 `RunTests` invariants ships with a deliberately broken
Store that the suite must catch AND name — 19 negative scenarios across the
main and cancellation suites. `RunTestsStrict` stretches wall-clock timings
for slow CI runners (`TimingScale`), and the opt-in `RunTestsContextAware`
pins cancellation semantics for context-honoring backends: a canceled call
returns the context error and does not consume the claim, so the retry after
a timeout stays processable.

### Runnable example + the recipes that close real gaps

- `go run ./example` — a consumer-owned in-memory `Store` validated by the
  contract suite, then a three-attempt exactly-once demo from the caller's
  perspective.
- Dedup + response replay — retriers get the original response back, not a
  bare 409 (the composition gap that stopped a real adoption evaluation);
  documented in the package docs.
- [Migration guide off the deprecated `MemoryStore`](../migrating-from-memorystore.md)
  with worked in-process and Redis implementations.

## Also in this release

- ADR-002/003/004 recorded and settled: the middleware boundary, no
  `BoundedStore` (restart durability is table stakes; an LRU-capped claim
  store silently sacrifices exactly-once), and a frozen `Store` interface
  (`Delete` deferred behind a demonstrated-need trigger).
- Common-pitfalls guide, backend feature matrix (Redis, PostgreSQL, MySQL,
  DynamoDB, SQLite/bbolt), and transient-error handling via
  `errorfamily.IsRetryable`.
- Governance: SECURITY.md, Contributor Covenant, issue templates, CODEOWNERS,
  an ADR index, the claim vocabulary, and a "why claims are TTL-windowed, not
  forever" FAQ entry.
- CI: Go compatibility matrix (go.mod toolchain + previous release), weekly
  strict-timing run, docs link check, govulncheck, and a fuzz budget raised
  to 3 minutes per target after a clean soak week (860M+ executions across
  the 4×15-minute soak, zero findings).

## Upgrade

```bash
go get github.com/larsartmann/go-idempotency@v0.3.0
```

No breaking changes to the `Store` interface or error semantics, and no new
runtime dependencies (`go-error-family` remains the only one). Purely
additive: the `middleware` package, new contract entry points, and docs.
