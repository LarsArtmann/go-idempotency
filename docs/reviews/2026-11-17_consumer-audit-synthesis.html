00Summary

Nobody in the fleet rejects go-idempotency for being badly built. They reject it because the contract cannot say the thing they need (permanent claims), because the docs overstate one redirect (DedupStore is not a Store), and because the part we actually ship that matters (contract/) is buried while the part nobody imports (middleware/) is presented as the headline. The library’s real fleet role is the contract layer of the dedup stack: 13 project checkouts import it, 8 run the contract suite, and 0 import the middleware.

The single highest-leverage action is an owner decision on idempotency.Forever. A cross-repo plan written 2026-09-16 (cv/docs/planning/2026-09-16_18-52_forever-ttl-ecosystem-execution-plan.md, M1–M18) has been waiting on that green light for two months, and three consumer domains (CV, taskqueue, DiscordSync) have permanent-dedupe needs the TTL-mandatory contract cannot express. Shipping it (or recording a REJECTED ADR) resolves the biggest recurring objection at once.

The bottom line Quality is not the problem; specification is. Decide Forever, fix the DedupStore wording, make contract/ the front door, and cut a release that reflects the five commits since v0.3.2. Everything else is polish.

◆What the audits already praise

Recorded so the fixes below do not read as a teardown. These are strengths consumers verified against the code, not marketing.

+
The contract suite is the adoption vector Eight fleet projects run contract.RunTests* against their own store or adapter (index, bank-sync, webphone, PapDashboard, KeyHolderAI, sperrmuell-direct, Standup-Killer, Zlota44). webphone calls it “13 concurrency/atomicity invariants for ~40 lines of test glue” and landed it the same day it was proposed.
+
Error classification is boringly correct No audit reports a problem with ErrDuplicate (Conflict → 409, non-retryable) or ErrInvalidTTL. index, browser-history and webphone pin the errors.Is chain end to end; the v0.3.1 sentinel-type fix is invisible because it removed a footgun.
+
The SQLite and TOCTOU docs are copied, not just read PapDashboard’s hand-rolled 182-line store follows this repo’s INSERT … ON CONFLICT + RowsAffected recipe verbatim; go-taskqueue calls the pitfalls section “excellent reference material”; invoices cites the fixed-width expiry trap by line.
+
Negative tests make the suite trustworthy 19 deliberately broken stores prove every invariant fires. No consumer reported a false pass, which is why the suite can be sold as a test-only dependency to projects that will not adopt the runtime.
+
The no-backend posture survived fleet review Every audit that rejects adoption accepts ADR-001’s charter. Nobody asked for a Redis driver; several asked for a copyable reference implementation and a clearer DedupStore story instead.

01Findings

These are the issues that need attention, ordered by impact.

Blocking · High impact

The contract cannot express a permanent claim

README.md:144 · docs/adr/004 · CV plan 2026-09-16 (M1–M18, owner-gated)

Every TTL-windowed rejection in the corpus traces to the same shape mismatch. CV needs event dedupe that never expires — it hand-rolled a forever store after a real corruption bug where a redelivered event folded twice (career-pipeline/eventstore/idempotency.go:41-48). go-taskqueue’s permanent DedupKey and invoices’ KSeF “an invoice may only be submitted once” guard are the same need. Our README answers with the poisoned-claim argument (a forever claim is a permanent lockout), which is correct for request claims. A cross-repo plan already draws that line — Forever is for consumer/event dedupe, ttl == 0 stays rejected, and request idempotency stays TTL-windowed — but no ADR in this repo records it, so the fleet has been waiting since 2026-09-16.

Fix: an owner decision, then M1–M4 If shipped: const Forever = time.Duration(math.MaxInt64) (stored directly, never computed — UnixNano wraps in 2262), a zero-time.Time entry in MemoryStore, and contract invariants ForeverNeverExpires / Seen/ForeverSurvives with negative stores. If rejected: write the REJECTED ADR citing the plan so consumers stop treating v0.4.0 as imminent and use domain permanence instead.
Blocking · High impact (docs)

“You do not need to write a backend” is only true if you do not use our Store

README.md:53 · doc.go:60-62 · docs/migrating-from-memorystore.md:20

metaengine.DedupStore is not a idempotency.Store: it takes a collection and an injected now, returns (seen bool, err) instead of sentinel errors, and adds DedupSweep. Three fleets independently wrote the adapter bridge — bank-sync (~110 lines, contract-tested), webphone (~40 lines, contract-tested), and this repo’s own consumers cannot use middleware.CommandIdempotency or contract.RunTests without one. The README sentence is accurate for direct capability use and misleading for every other reader, which is most of them.

Fix: document the seam, do not hide it Add a canonical adapter recipe (collection namespacing, seen → ErrDuplicate, ttl <= 0 → ErrInvalidTTL, injected clock) to doc.go and the migration guide, plus a two-row mapping table. Reword README:53 to “use system.Dedup() directly, or wrap it with the ~40-line adapter if you want this Store contract.”
Important · Medium impact

No way to record on success — the retryable-failure posture is inexpressible

store.go:54-111 · ADR-004 (Delete deferred)

webphone runs check-first / record-on-success: a failed attempt must stay retryable. With CheckAndRecord, a transport failure after the claim keeps returning 409 until TTL expiry; with Seen + Record you accept the TOCTOU race the README warns against. PapDashboard chose fail-open replay for the same reason. ADR-004 defers Delete/release without naming either consumer as evidence.

The gap is legitimate: a released claim weakens at-most-once and needs crash semantics. The problem is that the limitation is undocumented, so each consumer rediscovers it and builds a different workaround.

Important · Medium impact

The contract suite sleeps on wall-clock time

contract/contract_invariants.go:61,86,101,175 · contract/contract_timing.go

Four fixed time.Sleep(tm.waitAfter) calls carry the expiry invariants. webphone sets TimingScale: 5 to survive loaded runners and records the durable fix as “upstream — an injectable clock instead of wall sleeps.” This is the suite we sell as the library’s main value; its flake profile should not be the consumer’s problem. 

// Replace the fixed sleep with a bounded poll:
eventually(t, tm.waitAfter, func() bool {
    seen, err := store.Seen(ctx, key)
    return err == nil && !seen
})
Important · Medium impact

middleware/ has zero fleet consumers

middleware/ · ADR-005 (records 0/10) · confirmed 0/13

The command wrapper duplicates go-cqrs-lite’s middleware.CommandIdempotency, which takes the same idempotency.Store with a native command adapter; cqrs-htmx’s audit calls it “superseded here.” The HTTP adapter still has a plausible non-CQRS audience (Cyberdom, nsfw-classifier and media-atlas all name it as the standard answer for a mutating endpoint), but nobody has wired it either. The package is maintained, fuzzed and documented for no fleet consumer.

Fix: make the split explicit Keep the HTTP adapter. Decide Command’s fate at v1.0 (delete, or keep with a “non-CQRS stacks only” note pointing at the cqrs-lite factory). Refresh ADR-005’s evidence from 0/10 to 0/13 and put the pointer in the README next to the middleware section.
Important · Medium impact

The tree reads as dormant to every auditor

git: v0.3.2 (2026-11-03) + 5 commits, last commit 2026-11-04

Six audits record “HEAD +5, no tag”; CV’s 2026-11-13 pass says “upstream frozen (zero commits since 2026-11-04).” The five commits are a real improvement (test and suite files split under the 350-line cap, strict-timing CI fix) but ship nothing a consumer can depend on, so no one can cite a version. Dormancy also blocks the Forever decision from looking real.

Fix: cut v0.3.3 now, v0.4.0 when Forever is decided v0.3.3 is a no-API release: run scripts/pre-release-check.sh, move the [Unreleased] body into the tag, and push master plus tag together (lychee). Then v0.4.0 carries Forever or the REJECTED ADR.
Nice to have · Low impact

Response replay is still only a recipe

doc.go:262-290 · README.md:143

PapDashboard built a 182-line store including Stripe-style replay (returns the original status/aggregate/version) and concluded the library “has no API for it”; go-taskqueue calls the bare 409 a hole. The recipe exists but is invisible from the quick start, and the fleet keeps reimplementing it.

Keep replay out of Store — the derived-key recipe is the right shape. Make it runnable: an example/replay or an extension of example/main.go, linked from the README pitfalls entry.

Nice to have · Low impact

Two cheap docs fixes: constructor semantics and identity

store.go:130 · README “what it offers” · google-domain-detector audit

NewMemoryStore(sweepInterval) takes the sweep interval while the TTL is per call; browser-history’s audit initially read the argument as the TTL. One audit (google-domain-detector) invented an entire different library — Manager/Scenario/fs journal/ Prometheus metrics, file idempotency.go — that does not exist here (verified: zero ScenarioInFlight symbols anywhere in the fleet). That is the reviewer’s error, but a short “what this is / is not” block makes it much harder to repeat.

02What the solution could look like

Target state: the contract can say “forever” without weakening request idempotency, the docs describe the DedupStore seam honestly, the conformance suite waits on observable state instead of sleeping, and a tagged release matches the tree. 

// 1. Permanent claims stay a deliberate, separate semantic.
const Forever time.Duration = math.MaxInt64 // stored directly; never now.Add(Forever)

// ttl == 0 remains ErrInvalidTTL — a forgotten TTL stays loud.
// MemoryStore: zero time.Time entry means "never expires".
// Contract: ForeverNeverExpires, Seen/ForeverSurvives, Forever+Record no-op.

// 2. The DedupStore seam, documented instead of implied.
func (a *Adapter) CheckAndRecord(ctx context.Context, key string, ttl time.Duration) error {
    seen, err := a.dedup.DedupCheckAndRecord(ctx, a.collection, key, ttl, a.now().UTC())
    if err != nil {
        return err
    }
    if seen {
        return idempotency.ErrDuplicate
    }
    return nil
}

// 3. Contract waits on the store, not on the scheduler.
eventually(t, tm.waitAfter, func() bool {
    seen, err := store.Seen(ctx, key)
    return err == nil && !seen
})
This is the target Every recurring objection in the corpus maps to one of those three changes or to a docs sentence. None of them requires a production backend, a new dependency, or a breaking change to existing implementors — except Forever, which is additive but needs the owner’s semantic decision first.
