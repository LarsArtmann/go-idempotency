# go-idempotency v0.4.0

**Release date:** 2026-11-17 · **Compare:** v0.3.2...v0.4.0

v0.4.0 adds permanent claims: `idempotency.Forever` records a key that never
expires, for the cases where re-processing a duplicate corrupts state and a
TTL window is the wrong tool. It also makes the documented backend adapters
able to represent that claim, and fixes a PostgreSQL example that reported a
duplicate on the very first claim.

## Highlights

### Permanent claims (`Forever`)

`Forever` is `math.MaxInt64` and the only TTL that never expires:

```go
// Consumer/event dedupe: the duplicate window is the store's lifetime,
// not a request-retry horizon.
err := store.CheckAndRecord(ctx, "event:"+eventID, idempotency.Forever)
if errors.Is(err, idempotency.ErrDuplicate) {
    return nil // already applied
}
```

`MemoryStore` stores the zero `time.Time`, the sweeper skips it, and a live
claim is neither upgraded by a later `Forever` nor downgraded by a later short
TTL. `ttl == 0` still returns `ErrInvalidTTL`: forgetting a TTL must not
silently create a permanent claim. Five contract invariants with six negative
scenarios pin the semantics, so a backend can prove it maps the sentinel
correctly.

**Scope is deliberate.** `Forever` is for event/consumer dedupe, projection
replay, and permanent domain invariants. Request-facing `Idempotency-Key`
claims stay TTL-windowed: a permanent claim left by a crashed request is a
permanent lockout for that key. See
[docs/adr/006-forever-permanent-claims.md](../adr/006-forever-permanent-claims.md).

### The documented adapters can represent a permanent claim

The Redis adapter maps `Forever` to `SET` with no `EX`; the PostgreSQL/SQLite
adapters store a NULL `expires_at` and treat a claim as live while
`expires_at IS NULL OR expires_at > now()`, with a purge that skips NULL rows.
Previously every documented adapter computed `now.Add(ttl)`, so a consumer
copying one silently shortened a permanent claim to about 300 years of
`time.Time` — stored, but undefined once converted to `UnixNano` (2262).

## Behavior changes to review before upgrading

- **`Forever` claims never expire and are never reclaimed.** A claim recorded
  with `Forever` survives every sweep and every purge. Only use it where a
  duplicate is genuinely unrecoverable.
- **`Record` is a no-op on a live claim, in both directions.** A live
  short-TTL claim is not upgraded to `Forever`; a live `Forever` claim is not
  shortened. Expired claims are re-recorded with the fresh TTL.
- **Non-positive TTLs remain rejected.** `ErrInvalidTTL` (a `Rejection`,
  HTTP 400) for `ttl <= 0`; `Forever` is positive and accepted.

## Fixed

- **The documented PostgreSQL `CheckAndRecord` reported a duplicate on the
  first claim.** The example inserted with `ON CONFLICT ... DO UPDATE ...
  RETURNING expires_at` and then tested the returned expiry, which cannot
  distinguish a fresh insert from an existing live row. It now runs one
  conditional upsert and reads `RowsAffected()`.
- **Backend-primitive tables no longer teach an unreclaimable claim.** A bare
  `INSERT ... ON CONFLICT DO NOTHING` (or MySQL `INSERT IGNORE`) only frees the
  key once the expired row is purged, so a TTL-windowed claim outlives its TTL.
  The guidance now names a conditional upsert whose `DO UPDATE` only fires for
  an expired row.
- **Weekly scheduled CI's oldstable leg** bootstraps the pinned toolchain, so
  the strict-timing contract pass actually runs.

## Also in this release

- Test and contract-suite files split under the 350-line file-size cap; pure
  same-package moves, no behavior or API change.
- `scripts/pre-release-check.sh --only <gate>` runs a single gate, so one gate
  can be sabotage-proven without the full suite.
- The tag↔CHANGELOG parity gate understands the cut-but-untagged state.

## Upgrade

```bash
go get github.com/larsartmann/go-idempotency@v0.4.0
```

No new runtime dependencies: `go-error-family` remains the only one.
